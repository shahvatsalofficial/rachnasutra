# Rule examples: failing and passing inputs

Every example below is generated by running the real audit on the input shown (`npm run examples`). The same inputs are asserted in `test/rules.test.mjs`, so these pages cannot drift from the tested behaviour. HTML examples sit inside a minimal valid document so that other rules stay quiet.

> **Note:** "Passing" means this rule did not fire on the input. It does not mean the input is accessible or well designed.

## RS-A11Y-001: Image has no alt attribute

Category: accessibility. Default severity: high. Criterion: WCAG 1.1.1.

**Failing input**

```html
/* index.html */
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>T</title>
</head>
<body>
<main>
<img src="a.png" width="10" height="10">
</main>
</body>
</html>
```

**Result:** `RS-0001` [high/confirmed] Image has no alt attribute at `index.html:10`

**Passing input**

```html
/* index.html */
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>T</title>
</head>
<body>
<main>
<img src="a.png" alt="Company logo" width="10" height="10">
</main>
</body>
</html>
```

**Result:** rule did not fire
