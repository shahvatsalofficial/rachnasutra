Why people use it

1

Evidence, not opinions

Every finding shows the file, the line, the exact code and the fix. Contrast is measured, not guessed.

2

It says what it did not check

A coverage table lists what ran, what partly ran and what did not. Nothing unrun is shown as a pass. No fake score.

3

Reports anyone can read

A self-contained HTML page and a Markdown copy start with "Fix these first". Share them with a client or paste them into a pull request.

4

Proof the fix worked

verify compares against your baseline: resolved, remaining, and anything new you broke.

5

A CI gate you can trust

Exit code 1 only for confirmed, deterministic problems, so pull requests are blocked by facts and never by taste.

6

Works with your AI IDE

{{skills}} skills teach Claude Code, Cursor, Codex, Copilot and Gemini CLI to review safely, ask before editing, and verify afterwards.

Honest about its limits

Static analysis finds a portion of accessibility problems. It does not certify WCAG, ADA or any other conformance, and a clean report is not proof of an accessible site. On the W3C ACT test cases the rules reach 71% precision and 65% recall, and axe-core, which analyses a real browser DOM, is more accurate. We publish those numbers and the weaknesses behind them.

Start in 30 seconds

  1. Run it. npx rachnasutra audit . in any front-end project. Node.js 20 or newer.
  2. Open the report. rachnasutra-reports/latest.html opens in any browser.
  3. Fix the top items, then verify. npx rachnasutra verify --report rachnasutra-reports/latest.json .
  4. Add the gate. npx rachnasutra ci . in your pipeline.
